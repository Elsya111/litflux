# 图的含义与 agent 的判断

这里定义稳定的读图语言。业务抽象、对象归类、解释尺度、实虚线和坐标由 agent 决定；工具照声明呈现。字段查 [作者方式](semantic-authoring.md)，例子见 [项目模块](../examples/project-example.js)。

## 两张图

**业务分解图：这个业务由哪些子业务解释？** 父子边只表示解释上的组成，不表示执行先后、数据传递或调用顺序。即时/延后的实虚线法则不适用于这张图。

**内部流程图：当前业务的输入，怎样经过处理、判断和作用形成结果？** 展示当前这一层的全部对象与关系；选择节点只更新高亮和说明，不裁掉其他对象。

`business` 对象的 `detail` 就是进入后看到的内部图。判断、数据、资源、组件不成为分解图的子业务。

## 四类对象：按这里的作用判断

| 角色 | 含义 | 例子 |
| --- | --- | --- |
| business | 实际发生的处理或有共同职责的业务组合 | 规范化、检索、融合、写入 |
| data | 被传递或处理的内容 | 问题、清理后的文本、检索结果、路径 |
| resource | 被读写的稳定载体或共享状态 | 文件、数据库、配置、循环累计列表 |
| component | 提供这次调用能力的实现 | 写入器、解析器、模型客户端 |

文件内容是数据，文件本体是资源，路径是定位数据；写入器是组件，调用写入器是业务。不能按类名、参数位置或文件名机械归类。

判断（decision）和循环是控制结构，不是第五、第六类业务对象。boundary 只在需要入口/结束标记时使用。不为了凑齐四类造对象，也不隐藏影响结果的资源作用或提供方。

## 数据、控制与边注

数据关系表达"内容 → 处理/判断 → 结果"。实质转换由业务承担；内容发生实质变化时交代新的阶段身份。直接传递同一内容可以复用它，不必为每次赋值造节点。

控制关系交代条件、先后或失败路径。判断的判据要能追溯；条件出口写清各自结果。互斥分支不是必须同时到齐的输入。

资源作用交代实际读写方向与动作；组件能力交代谁提供调用。

**边注属于边。** 它说明传什么、何时走或作用是什么，保持完整、清楚对应、视觉轻于对象。新的转换动作应由业务对象表达。对于重复啰嗦的边注不必强加，边注的意义在于帮助理解。

## 实虚线只用于内部流程图的数据依赖边

**agent 判断并声明，工具只绘制，不从拓扑重新推断。**

- **实线：即时承接。** 内容直接交给这条因果链紧接着的处理。一个节点可以有多个实线输入，一个来源也可以立即交给多个处理。
- **虚线：保留后用。** 同一份内容跨过已解释的中间环节，保留给后续处理使用。它仍是必要依赖，不表示可选、次要或"当前没选中"。

例如 A→B→C、D→E→F 都是即时承接时，额外 B→E 也可以是实线——跨到另一条链不等于延后。若已有 B→C→E，而 B 的同一内容另被 E 保留使用，那么额外 B→E 用虚线。

线型静态：不随阅读步骤、条件选择、布局、边长或窗口宽度变化。

| 具体关系 | 实虚线法则 |
| --- | --- |
| 数据进入业务或判断，以及处理产出数据 | 适用，由作者声明 |
| 判断的条件出口、普通控制与异常 | 不适用，用独立控制标识和明确标签 |
| 循环回指 | 不适用，用独立回指箭头 |
| 资源作用、组件能力 | 不适用，保持各自标识 |
| 业务分解图的父子边 | 不适用，只表示组成 |

**判断理由要写下来。** 一条数据边如果还存在经过其他节点的路径，就必须写 `timingNote`：说明为什么它是即时或保留。工具只判断"有没有中间路径"，不判断"应该是什么线型"；复核的人读理由即可，不用重推整张图。

两位作者对同一张图判得不必完全一样，读者依据是图例和边注，不是"作者保证一致"。

## 循环与阅读

循环用显式 `loop` 关系表达，不构造图环、不进拓扑检查、不当作阅读前驱。可以概括为业务，也可以展开代表性一轮，画出循环体、回指和退出条件。

**按实线阅读是静态导览。** agent 可给 `reading` 优先顺序；程序沿声明的即时关系推进，在汇合处补齐全部有效依赖（包括虚线）。资源和组件不作为执行步骤。循环体说明一轮后提示按条件重复，不模拟真实执行次数。

## 分解尺度

默认展开到影响结果的关键机制。节点还藏着重要选择、转换、组合或外部作用，展开会增加理解，就继续；已经讲清输入、处理、结果和条件，再拆主要增加赋值、包装或常规库调用时，就停在解释与源码。

用户可要求快速总览、局部深入或参考层数；未指定部分用默认。不同子树可以不同深度，没有固定层数或节点数量上限。

## 呈现与验收

agent 设计每个视图的主链、分支、边注、留白和折返；程序执行这份布局，不再换算法重排。字距、配色和主题由工具统一，保证跨项目一致。

工具报告的是客观缺陷：节点重叠、越界、边注压节点或互相重叠、边注离所属边太远、连线穿过其他对象、文字超出形状、纵横比极端。工具不评价"讲没讲清"和"好不好看"。

交付状态只有三种：`draft`（能打开）、`checked`（声明一致 + 几何无缺陷 + 交互通过）、`reviewed`（另一上下文的 agent 复核过）。读者位和审美判断仍由人做，工具不宣称验证过语义。
