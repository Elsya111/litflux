# 布局参考：让关系容易追踪

这些是可借鉴的选择，不是模板。Agent 根据源码、解释层级和读者需要决定布局；同一份解释可以有不同的好画法。坐标 API 见[作者方式](semantic-authoring.md)，可运行场景见[参考模块](../examples/layout-examples.js)。

## 先找读者要追的结果

可以先摆出主要输入、关键处理和结果，再安排分支、附加输入、资源与组件。视觉主链不等于唯一实线链；并行汇合可以同时保留多个即时依赖。

| 场景 | 可以考虑 | 换一种画法的时机 |
| --- | --- | --- |
| 短主链 | 单行或单列，输入到结果方向连续 | 边注变挤、窗口过宽时改折返或纵向 |
| 长主链 | 在阶段边界折返，下一排反向延续 | 反向箭头不易追踪时，用同向多排并留转接通道 |
| 并行汇合 | 支路分轨，结果靠近汇合处理 | 支路长短差异大时，可以围绕共同消费者排列 |
| 互斥分支 | 判断旁分区，公共输入留在分支外 | 分支内部过复杂时，把其职责放入可进入的业务 |
| 循环与状态 | 解释代表性一轮，状态靠近读写处，回指另留空间 | 循环细节无助于当前问题时，可概括为业务并解释 |

长依赖通常适合走外侧，但也可以利用内部留白。折返是排版，loop 是业务语义；距离不决定实虚线。交叉不表示连接，尽量让不同关系的来源与去向可辨认。例如“发布”写入两个资源，可分别从发布节点出线，避免其中一条看起来从旁边的条件线分叉。

## 用实际尺寸安排边注

```js
s.node('input', 100, 150).node('work', 400, 150);
const a = s.nodeBox('input'), b = s.nodeBox('work');
const gap = b.left - a.right;
const maxWidth = gap - 26; // 本场景留出背景和箭头附近的空间，可自行调整
const note = s.measure('候选与计算证据', {maxWidth});
s.edge('consume', {
  sides: ['right', 'left'],
  noteAt: [(a.right + b.left) / 2, 150],
  noteWidth: maxWidth,
});
// note.boxHeight 可用于安排相邻轨道；空间不足时也可换线段或改走线。
```

这里假设两节点水平排列且间隙足够。竖向、折返或曲线可以选择另一段较宽的留白，不需要把文字塞进端点间距。`nodeBox` 使用作者坐标；画布平移和查看器缩放不改变它。显式 `noteWidth` 控制文本换行，`measure` 的 `boxWidth/boxHeight` 已包含背景留白。

边注中心靠近所属边还不够：旁边有多条边时，也要能看出它属于哪一条。完整说明可以换行；重复的可见标签可以省略，关系仍可选择。不需要为了适应默认宽度把有用内容缩成几个字。

## 快速看反馈，再由作者决定

`--geometry-only` 运行实际绘制和几何检查，适合改坐标时使用。报告的 `suggestion.noteAt` 是当前路径上一个局部可放的位置，采用前仍可考虑阅读方向和整体留白；没有候选时，可以改宽度、线路或节点位置。程序不会自动挪动对象。

几何通过后用完整构建检查交互，并看实际截图。全图适配方便定位，正文按原始大小阅读。狭长画布未必错误；若读者需要频繁来回拖动，可尝试折返或改分解，而无需追求固定比例、固定节点数或同一种排版。
